Objetivo:
Generar un diagrama de clases UML completo del proyecto HotelNova (Java SE + JDBC + capas), reflejando estructura real de paquetes, clases, interfaces, atributos, métodos y relaciones.

Instrucciones para la IA de diagramas:

1) Alcance del diagrama
- Incluir clases e interfaces de estos paquetes:
  - model
  - dao
  - dao.impl
  - services
  - services.interfaces
  - controller
  - menu
  - utils
  - config
  - db
  - exceptions
- Excluir:
  - Main (opcional, solo si se desea mostrar punto de entrada)
  - archivos de test

2) Clases de dominio (model)
- Room:
  - atributos: id:int, room_type:String, room_number:int, room_capacity:int, room_price:double, room_state:String, isActive:boolean, createdAt:LocalDateTime
  - getters/setters correspondientes
- Guest:
  - atributos: id:int, isActive:boolean, name:String, email:String
  - getters/setters correspondientes
- User:
  - atributos: id:int, email:String, password:String, rol:String, name:String
  - getters/setters correspondientes
- Reservation:
  - atributos: id:int, id_room:int, id_guest:int, total_nights:int, day_in:LocalDate, day_out:LocalDate, check_in:boolean, check_out:boolean
  - getters/setters correspondientes

3) DAO e implementaciones
- GenericDAO<T, ID> (interface):
  - save(entity):T
  - findById(id):Optional<T>
  - findAll():List<T>
  - update(entity):boolean
  - deleteById(id):boolean

- RoomDAO extends GenericDAO<Room,Integer>:
  - findByNumber(int):Optional<Room>
  - findByType(String):List<Room>
  - findByState(String):List<Room>
  - updateState(int,String):boolean
  - updateIsActive(int,boolean):boolean

- GuestDAO extends GenericDAO<Guest,Integer>:
  - findByEmail(String):Optional<Guest>
  - findByIsActive(boolean):List<Guest>
  - updateIsActive(int,boolean):boolean

- UserDAO extends GenericDAO<User,Integer>:
  - getByRol(String):List<User>
  - getByEmail(String):Optional<User>

- ReservationDAO extends GenericDAO<Reservation,Integer>:
  - findByRoom(int):List<Reservation>
  - findActiveByRoom(int):Optional<Reservation>
  - findActiveById(int):Optional<Reservation>
  - hasOverlappingReservation(int,LocalDate,LocalDate):boolean

- GenericDAOImpl<T,ID> (abstract):
  - implementa GenericDAO
  - atributo protegido: cm:ConnectionManager
  - métodos abstractos de mapeo SQL/params

- Implementaciones concretas:
  - RoomDAOImpl extends GenericDAOImpl<Room,Integer> implements RoomDAO
  - GuestDAOImpl extends GenericDAOImpl<Guest,Integer> implements GuestDAO
  - UserDAOImpl extends GenericDAOImpl<User,Integer> implements UserDAO
  - ReservationDAOImpl extends GenericDAOImpl<Reservation,Integer> implements ReservationDAO

4) Services e interfaces
- IAuthService:
  - register(email,password,rol,name):User
  - login(email,password):User
- IRoomService:
  - createRoom(roomNumber,roomType,capacity,price,state):Room
  - updateRoom(Room):boolean
  - deleteRoom(int):boolean
  - toggleActive(int,boolean):boolean
  - listRooms():List<Room>
  - listRoomsByType(String):List<Room>
  - listRoomsByState(String):List<Room>
- IGuestService:
  - createGuest(name,email):Guest
  - updateGuest(Guest):boolean
  - deleteGuest(int):boolean
  - toggleActive(int,boolean):boolean
  - findByEmail(String):Guest
  - listGuests():List<Guest>
  - listActiveGuests():List<Guest>
- IUserService:
  - createUser(...):User
  - updateUser(User):boolean
  - deleteUser(int):boolean
  - listUsers():List<User>
  - listByRol(String):List<User>
- IReservationService:
  - checkIn(roomId,guestId,dayIn,dayOut):Reservation
  - updateReservation(Reservation):Reservation
  - deleteReservation(int):boolean
  - checkOut(int):double
  - listReservations():List<Reservation>
  - listReservationsByRoom(int):List<Reservation>
- IExportService:
  - exportRoomsCsv(String):void
  - exportActiveReservationsCsv(String):void

- Implementaciones:
  - AuthService implements IAuthService
  - RoomService implements IRoomService
  - GuestService implements IGuestService
  - UserService implements IUserService
  - ReservationService implements IReservationService
  - ExportService implements IExportService

5) Controllers
- AuthController -> depende de IAuthService
- RoomController -> depende de IRoomService
- GuestController -> depende de IGuestService
- UserController -> depende de IUserService
- ReservationController -> depende de IReservationService
- ExportController -> depende de IExportService

Mostrar que los controladores delegan en interfaces de servicio (no en implementación concreta).

6) Menús (JOptionPane)
- AdminMenu:
  - compone GuestMenu, RoomMenu, ReservationMenu, ExportMenu
- GuestMenu -> usa GuestController
- RoomMenu -> usa RoomController
- ReservationMenu -> usa ReservationController
- ExportMenu -> usa ExportController

Relaciones sugeridas:
- composición fuerte desde AdminMenu hacia submenús.
- dependencia desde cada menú hacia su controller.

7) Utilidades e infraestructura
- AppConfig (singleton)
- ConnectionManager (singleton, usa AppConfig)
- PasswordUtil (métodos estáticos)
- AppLogger (métodos estáticos)
- CsvUtil (métodos estáticos)
- TableFormatterUtil (métodos estáticos)

8) Excepciones
- BusinessException extends RuntimeException
- NotFoundException extends RuntimeException

9) Relaciones UML que deben verse explícitamente
- Herencia:
  - *DAOImpl -> GenericDAOImpl
  - BusinessException / NotFoundException -> RuntimeException
- Realización (implements):
  - *Service -> I*Service
  - *DAOImpl -> *DAO
- Dependencias:
  - Services -> DAO
  - Controllers -> interfaces de service
  - Menus -> Controllers
  - ReservationService -> RoomDAO, GuestDAO, ReservationDAO, AppConfig, ConnectionManager
- Asociación de dominio:
  - Reservation referencia Room y Guest por id (no objeto directo), anotar como asociación lógica por clave foránea.

10) Presentación del diagrama
- Separar por paquetes/capas (swimlanes o grupos):
  - UI (menu + controller)
  - Business (services + interfaces)
  - Data (dao + impl)
  - Domain (model)
  - Infra/Utils (config, db, utils, exceptions)
- Incluir visibilidad de atributos y métodos (+/-/#).
- Incluir tipos de retorno y parámetros en los métodos principales.
- Mantener legibilidad: evitar saturar con getters/setters si la herramienta permite colapsarlos.
